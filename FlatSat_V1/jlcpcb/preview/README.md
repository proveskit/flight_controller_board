# FlatSat_V1 production PREVIEW -- NOT the order package

Generated by `kicad-cli` (no GUI, no JLCPCB plugin) from the Phase-2 stage-6 (silkscreen + docs +
preview) board, for the design review only. **This is not what gets ordered.** Per
`docs/flatsat/2026-09-14_phase2_layout/00_pm_brief.md` §1 and `CLAUDE.md`'s pre-order procedure
step 6, the official production package comes from the owner's own JLCPCB-plugin GUI pass
(`project.db`, F8 Update PCB from Schematic, Generate) over the reviewed, order-ready board --
never from this directory, and never from an agent.

Source board: `.flatsat_work/phase2/round3/layout_finish/work/FlatSat_V1.kicad_pcb` (stage-6
silkscreen pass output; see `layout_report.md`). Generated 2026-09-23.

| Dir | Contents | Command |
|---|---|---|
| `gerber/` | 11 Gerber layers (F/In1/In2/B Cu, F/B SilkS, F/B Mask, F/B Paste, Edge.Cuts) + job file, using the board's own stored plot params (inherited byte-for-byte from `FC_V5e_Production_Rev2`, confirmed identical `pcbplotparams` block) | `kicad-cli pcb export gerbers --board-plot-params -l "F.Cu,In1.Cu,In2.Cu,B.Cu,F.SilkS,B.SilkS,F.Mask,B.Mask,F.Paste,B.Paste,Edge.Cuts"` |
| `drill/` | PTH/NPTH Excellon drill files (mm, absolute origin, decimal zeros) + PDF drill maps + text report | `kicad-cli pcb export drill --excellon-separate-th --generate-map --map-format pdf --generate-report` |
| `pos/` | Component placement (both sides, mm, CSV) | `kicad-cli pcb export pos --side both --format csv --units mm` |
| `bom/` | Grouped BOM (Designator/Value/Footprint/LCSC/Datasheet/Quantity/DNP, grouped by Value+Footprint+LCSC Part) from the schematic | `kicad-cli sch export bom --fields "Reference,Value,Footprint,LCSC Part,Datasheet,QUANTITY,DNP" --group-by "Value,Footprint,LCSC Part"` |

Not included here (owner GUI step only): JLCPCB-plugin-specific CPL format, `project.db`
LCSC-column sync/export, rotation corrections from `corrections.db`, live cart.jlcpcb.com stock
verification. `jlcpcb/project.db` was not read or written by this pass.

This BOM's `LCSC` column is the schematic `LCSC Part` field, which is **not** what the FC's own
heritage parts are ordered from (`CLAUDE.md`: heritage LCSC numbers live only in `jlcpcb/project.db`,
read-only here) -- so every heritage-only BOM group (81 of 182) reads blank here by repo convention,
not by omission. Of the 101 BOM groups that include a Phase-2 (200+) refdes, 80 carry an LCSC number
and the remaining 21 are exactly the new test points (`TP2xx`-`TP7xx`), which per brief ruling S5
carry no LCSC on this board, matching the FC's own `TP1`-`TP8` convention -- so every new part that
should have an LCSC number has one in this BOM.
